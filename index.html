Prérequis & Installation

Installer Ollama, un modèle local et OpenClaw, puis vérifier que ton assistant répond.

Ce qu'il te faut

  • Système : macOS, Linux, ou Windows avec WSL2.
  • Node.js : 24.16 ou plus récent dans la série 24, ou 26.1 et plus (26 recommandé). Vérifie avec node --version.
  • Mémoire : 8 Go de RAM au minimum pour un petit modèle local, 16 Go ou plus pour être à l'aise.
  • Docker : facultatif ici, nécessaire pour la sandbox de la session 3.
  • Un compte Telegram pour la session 2.

ℹ️ Version de référence

Ce cours est vérifié sur OpenClaw 2026.11.3 (10 novembre 2026). OpenClaw évolue vite : openclaw update met ton installation à jour, et openclaw doctor --fix migre une ancienne configuration.

1. Installer Ollama et un modèle local

Ollama fait tourner le modèle de langage sur ta machine. Ses données ne quittent pas ton ordinateur.

bash
curl -fsSL https://ollama.com/install.sh | sh
ollama pull gemma4
ollama list

Sur Windows, installe Ollama dans WSL2 avec la même commande, ou utilise l'installeur de ollama.com/download.

💡 Quel modèle ?

OpenClaw a besoin d'un modèle qui sait appeler des outils et dispose d'au moins 16 000 tokens de contexte. gemma4 est le modèle que l'assistant d'OpenClaw propose par défaut. Avec plus de mémoire, qwen3.5:27b ou gpt-oss:20b sont plus fiables.

2. Installer OpenClaw

macOS, Linux et WSL2 :

bash
curl -fsSL https://openclaw.ai/install.sh | bash

Windows (PowerShell) :

powershell
iwr -useb https://openclaw.ai/install.ps1 | iex

Alternative avec npm :

bash
npm install -g openclaw@latest --allow-scripts=openclaw

3. L'assistant de configuration

Le script d'installation lance l'assistant automatiquement. Choisis Quick start : il détecte ton modèle Ollama, le teste avec une vraie requête et enregistre la configuration. Si tu as installé avec npm, lance-le toi-même :

bash
openclaw onboard --install-daemon

Cette variante ouvre l'assistant complet (modèle, canaux, skills) et installe en plus le service d'arrière-plan. Pour le modèle, choisis Ollama, puis Local only.

⚠️ Accès complet par défaut

Le Quick start crée un agent main avec un accès complet à ta machine : il peut lire, écrire et exécuter des commandes. C'est pratique pour apprendre, mais nous resserrerons ces droits dans la session 6 (Sécurité avancée).

4. Vérifier l'installation

bash
openclaw --version
openclaw doctor
openclaw status
openclaw dashboard

openclaw doctor diagnostique et répare la configuration. openclaw dashboard ouvre l'interface web locale de contrôle (Control UI), et openclaw tout seul ouvre une interface dans le terminal.

Le défi 15 minutes

bash
# 1. Moteur IA local + modèle
curl -fsSL https://ollama.com/install.sh | sh
ollama pull gemma4

# 2. OpenClaw + assistant (Quick start → Ollama)
curl -fsSL https://openclaw.ai/install.sh | bash

# 3. Vérifier et ouvrir le tableau de bord
openclaw status
openclaw dashboard

Session 1

Fondations & Architecture

Comprendre comment fonctionne OpenClaw (Gateway, agent, modèle, canaux) et brancher ton assistant sur un modèle 100 % local.

OpenClaw en une phrase

OpenClaw est un assistant IA personnel open source qui tourne sur ta machine. Tu lui écris depuis ta messagerie (Telegram, WhatsApp, Signal, Discord…), et il répond, se souvient et agit : il lit et écrit des fichiers, lance des commandes, navigue sur le web, programme des tâches.

Les briques de l'architecture

BriqueRôleOù ?
GatewayLe serveur central : il reçoit les messages des canaux, les route vers l'agent et garde les sessions127.0.0.1:18789
AgentL'assistant lui-même (par défaut main), avec sa personnalité, ses règles et sa mémoire~/.openclaw/workspace
ModèleLe « cerveau » : un LLM local (Ollama) ou dans le cloudex. ollama/gemma4
CanauxLes messageries par lesquelles tu lui parlesTelegram, WhatsApp, Signal…
Outils & skillsCe que l'agent sait faire : fichiers, commandes, web, automatisationsOutils intégrés + skills/

La configuration est dans ~/.openclaw/openclaw.json (format JSON5). La Gateway la recharge automatiquement quand tu la modifies.

La boucle de l'agent

  • Perception : un message arrive par un canal ; la Gateway l'associe à une session.
  • Réflexion : le modèle lit le message avec le contexte de l'agent (ses fichiers d'instructions, sa mémoire, l'historique) et choisit la suite.
  • Action : il appelle un outil — lire un fichier, lancer une commande, chercher sur le web.
  • Observation : le résultat de l'outil revient au modèle, qui continue ou répond.

Chatbot ou agent ? Un chatbot répond à un message. Un agent enchaîne plusieurs actions avec des outils jusqu'à atteindre un objectif.

Brancher le modèle local

L'assistant de configuration l'a normalement fait. Pour le régler à la main :

bash
# Le modèle doit être téléchargé dans Ollama
ollama pull gemma4

# Ollama local : n'importe quelle valeur de clé convient
export OLLAMA_API_KEY="ollama-local"

# Choisir le modèle par défaut de l'agent
openclaw models list
openclaw models set ollama/gemma4

Ce que cela écrit dans ~/.openclaw/openclaw.json :

json5 · openclaw.json
{
  agents: {
    defaults: {
      model: { primary: "ollama/gemma4" },
    },
  },
}

⚠️ Pas de /v1

Si tu indiques une adresse Ollama à la main, utilise l'API native http://127.0.0.1:11434, jamais l'URL compatible OpenAI /v1 : elle casse les appels d'outils.

Premier échange

bash
# Envoyer un message à l'agent depuis le terminal
openclaw agent --agent main --message "Présente-toi en deux phrases."

# Ou discuter dans le terminal
openclaw

Local ou cloud : être lucide

Un modèle local garde tes conversations chez toi et ne coûte rien à l'usage. La documentation d'OpenClaw rappelle aussi ses limites : les petits modèles suivent moins bien les instructions et résistent moins bien à l'injection de prompt. Avec un modèle local, on garde donc des outils limités et une sandbox (sessions 3 et 6). Tu peux définir un modèle de secours (par exemple Mistral, session 5) avec agents.defaults.model.fallbacks, en sachant que les messages concernés partiront alors chez ce fournisseur.

1. Sur quel port la Gateway OpenClaw écoute-t-elle par défaut ?

💬 18789 est le port de la Gateway ; 11434 est celui d'Ollama.

2. Quelle différence entre un chatbot et un agent OpenClaw ?

💬 L'agent boucle : il agit avec des outils, observe le résultat et décide de la suite.

Le workspace : la mémoire et le caractère de l'agent

Chaque agent a un dossier de travail, par défaut ~/.openclaw/workspace. Les fichiers Markdown qu'il contient sont lus à chaque session :

FichierContenu
AGENTS.mdLes règles de travail et les consignes, y compris la section ## Tools sur l'usage des outils
SOUL.mdLa personnalité : ton, valeurs, limites
USER.mdCe que l'agent sait de toi (facultatif)
IDENTITY.mdSon nom et sa présentation
MEMORY.md et memory/Sa mémoire à long terme et ses notes du jour (session 3)

ℹ️ Changements récents

TOOLS.md n'est plus utilisé : son contenu va dans AGENTS.md. HEARTBEAT.md n'est plus lu non plus. openclaw doctor --fix migre automatiquement un ancien workspace.

Personnaliser Lobster-01

Ouvre ~/.openclaw/workspace/SOUL.md et remplace son contenu :

markdown · SOUL.md

Tu es Lobster-01, l'assistant de veille IA de ton utilisateur.
- Tu réponds en français, de façon concise et concrète.
- Tu cites toujours tes sources quand tu résumes une information.
- Tu demandes confirmation avant toute action irréversible (suppression, envoi, achat).

Puis ajoute tes règles dans AGENTS.md :

markdown · AGENTS.md
## Veille
- Chaque résumé tient en 5 points maximum.
- Enregistre les sujets suivis dans memory/.

## Tools

Pas besoin de redémarrer : ces fichiers sont relus à chaque nouvelle session. Tape /new dans la conversation pour en ouvrir une.

Connecter Telegram

  1. Dans Telegram, ouvre @BotFather, envoie /newbot et copie le token du bot.
  2. Déclare le canal et vérifie la connexion :
bash
openclaw channels add --channel telegram --token <token-du-bot>
openclaw channels status --probe
  1. Envoie un premier message privé à ton bot. Il te répond par un code d'appairage.
  2. Approuve ce code depuis ton terminal :
bash
openclaw pairing list telegram
openclaw pairing approve telegram <CODE>

Les codes expirent au bout d'une heure. Une fois approuvé, tu peux discuter avec ton agent depuis ton téléphone.

Qui a le droit de parler à ton agent ?

Le réglage dmPolicy décide qui peut écrire à l'agent en privé :

ValeurEffet
pairing (défaut)Un inconnu reçoit un code ; rien ne passe tant que tu ne l'as pas approuvé
allowlistSeuls les identifiants listés dans allowFrom sont acceptés
openTout le monde (exige allowFrom: ["*"]) — à éviter
disabledMessages privés désactivés
json5 · openclaw.json
{
  channels: {
    telegram: {
      enabled: true,
      dmPolicy: "pairing",
      groups: { "*": { requireMention: true } },
    },
  },
}

Dans un groupe, requireMention: true oblige à mentionner le bot pour qu'il réagisse.

Session 3

Skills, Mémoire & Sandbox

Étendre ton agent avec des skills, lui donner une mémoire qui reste chez toi et isoler ses actions dans une sandbox Docker.

Les skills : apprendre de nouveaux savoir-faire

Un skill est un dossier contenant un fichier SKILL.md : un mode d'emploi que l'agent lit quand la tâche s'y prête. OpenClaw en fournit déjà (météo, PDF, GitHub, Notion…), et le registre public ClawHub en propose des milliers.

bash
# Skills disponibles et utilisables
openclaw skills list --eligible

# Chercher sur ClawHub
openclaw skills search "calendar"

# Vérifier puis installer un skill
openclaw skills verify @auteur/nom-du-skill --card
openclaw skills install @auteur/nom-du-skill

⚠️ Un skill tiers est du code non fiable

La documentation d'OpenClaw est claire : lis le SKILL.md avant de l'activer, consulte le résultat de l'analyse de sécurité affiché sur ClawHub, et préfère la sandbox pour les tâches risquées.

Créer ton propre skill

Crée ~/.openclaw/workspace/skills/revue-presse/SKILL.md :

markdown · SKILL.md
---
name: revue-presse
description: Prépare une revue de presse IA en français à partir de sources fiables.
metadata: { "openclaw": { "emoji": "📰" } }
---

# Revue de presse IA

Quand l'utilisateur demande une revue de presse :
1. Cherche les actualités IA des dernières 24 h avec web_search.
2. Garde 5 sujets maximum, en privilégiant les sources primaires.
3. Pour chacun : un titre, deux phrases de résumé, le lien.
4. Enregistre la liste des sujets dans memory/ pour éviter les doublons.

Les champs name et description sont obligatoires ; la description sert à l'agent pour savoir quand utiliser le skill. Vérifie qu'il est reconnu :

bash
openclaw skills info revue-presse

La mémoire

La mémoire de l'agent est faite de simples fichiers Markdown dans son workspace :

  • MEMORY.md : la mémoire à long terme, chargée au début de chaque session ;
  • memory/AAAA-MM-JJ.md : les notes du jour ; celles d'aujourd'hui et d'hier sont rechargées automatiquement.

Pour retrouver une information plus ancienne, l'agent fait une recherche sémantique dans ces fichiers (outils memory_search et memory_get).

⚠️ Piège RGPD

Par défaut, cette recherche calcule ses embeddings avec l'API OpenAI : des extraits de ta mémoire partent alors chez OpenAI. Pour rester 100 % local, passe sur Ollama.

bash
ollama pull nomic-embed-text
json5 · openclaw.json
{
  memory: {
    search: { provider: "ollama", model: "nomic-embed-text" },
  },
}
bash
openclaw memory index --force
openclaw memory status
openclaw memory search "politique de rétention"

openclaw configure --section memory fait le même réglage de façon guidée.

La sandbox Docker

Par défaut, l'agent exécute ses outils directement sur ta machine. La sandbox les fait tourner dans un conteneur Docker isolé : sans réseau, système en lecture seule, sans privilèges.

Construis d'abord l'image (installation npm) :

bash
docker build -t openclaw-sandbox:bookworm-slim - <<'DOCKERFILE'
FROM debian:bookworm-slim
ENV DEBIAN_FRONTEND=noninteractive
RUN apt-get update && apt-get install -y --no-install-recommends \
  bash ca-certificates curl git jq python3 ripgrep \
  && rm -rf /var/lib/apt/lists/*
RUN useradd --create-home --shell /bin/bash sandbox
USER sandbox
WORKDIR /home/sandbox
CMD ["sleep", "infinity"]
DOCKERFILE

Puis active la sandbox :

json5 · openclaw.json
{
  agents: {
    defaults: {
      sandbox: { mode: "non-main", scope: "session", workspaceAccess: "none" },
    },
  },
}
RéglageValeurs
modeoff (défaut) · non-main : tout sauf ta session principale, donc tous les groupes et canaux · all : toutes les sessions
scopeagent (défaut) · session · shared
workspaceAccessnone (défaut, espace isolé) · ro (lecture seule) · rw (lecture-écriture)
bash
openclaw sandbox explain
openclaw sandbox list

💡 Ce que la sandbox ne fait pas

La Gateway reste sur ta machine : seule l'exécution des outils est isolée. La documentation précise que ce n'est « pas une frontière de sécurité parfaite ». On la combine avec des restrictions d'outils (session 6).

Session 4

Automatisation, Multi-agents & 24/7

Faire travailler ton agent tout seul à heures fixes, répartir les rôles entre plusieurs agents et le garder actif en continu.

Les automatisations

Une automatisation lance l'agent selon un planning, dans une session isolée, puis t'envoie le résultat. On place le planning en premier et la consigne en second :

bash
# Tous les jours à 7 h
openclaw automations create "0 7 * * *" \
  "Prépare ma revue de presse IA avec le skill revue-presse." \
  --name "Brief du matin" \
  --tz "Europe/Paris"

# Toutes les heures
openclaw automations create "every 1h" \
  "Vérifie l'espace disque et préviens-moi s'il reste moins de 10 %." \
  --name "Surveillance disque"

openclaw automations list
openclaw automations run <job-id>

openclaw cron est un alias de openclaw automations. Par défaut, le résultat d'une tâche isolée t'est annoncé ; --no-deliver le garde en interne, --webhook <url> l'envoie à une URL.

Le heartbeat

Le heartbeat réveille l'agent à intervalle régulier (toutes les 30 minutes par défaut) pour qu'il vérifie s'il a quelque chose à faire.

json5 · openclaw.json
{
  agents: {
    defaults: {
      heartbeat: { every: "1h" },   // "0m" désactive
    },
  },
}

Plusieurs agents

Tu peux faire tourner plusieurs agents, chacun avec son workspace, son modèle et ses canaux. Les bindings décident quel agent répond sur quel canal :

json5 · openclaw.json
{
  agents: {
    entries: {
      veille: { name: "Veille IA", workspace: "~/.openclaw/workspace-veille", model: "ollama/gemma4" },
      perso:  { name: "Assistant perso", workspace: "~/.openclaw/workspace-perso", model: "ollama/qwen3.5:27b" },
    },
  },
  bindings: [
    { agentId: "veille", match: { channel: "telegram", accountId: "*" } },
    { agentId: "perso",  match: { channel: "signal", accountId: "*" } },
  ],
}
bash
openclaw agents list --bindings

Un agent peut aussi déléguer une sous-tâche à un sous-agent (outil sessions_spawn), qui travaille dans sa propre session puis rapporte son résultat. Dans la conversation, /subagents list les affiche.

ℹ️ Ancien format

agents.list est l'ancien format de déclaration ; agents.entries le remplace. openclaw doctor --fix fait la migration.

Rester actif 24 h/24

La Gateway doit tourner en permanence pour recevoir tes messages et lancer les automatisations. Installe-la comme service système (LaunchAgent sur macOS, service systemd utilisateur sur Linux, tâche planifiée sur Windows) :

bash
openclaw gateway install
openclaw gateway status

# Linux : garder le service actif après déconnexion
sudo loginctl enable-linger $(whoami)

openclaw onboard --install-daemon fait la même chose pendant l'installation.

Sur un serveur européen

Pour ne pas dépendre de ton ordinateur, installe OpenClaw sur un VPS européen : Hetzner (Allemagne), OVH ou Scaleway (France). Garde la Gateway sur loopback et accède-y à distance par un tunnel SSH ou Tailscale :

bash
# Depuis ton ordinateur : le tableau de bord distant devient accessible sur localhost:18789
ssh -N -L 18789:127.0.0.1:18789 utilisateur@mon-serveur

Un modèle local sur VPS demande beaucoup de RAM (16 Go et plus) ; sur une petite machine, le modèle tourne souvent ailleurs, ce qui change le bilan de confidentialité.

Surveiller et mettre à jour

bash
openclaw status --all
openclaw health
openclaw logs --follow
openclaw update

openclaw status --all produit un diagnostic qui masque les secrets, à partager sans risque.

Session 5

Personnaliser son agent avec Mistral

Faire tourner ton agent sur des modèles Mistral, en local ou via l'API européenne, et les adapter à tes besoins.

Pourquoi Mistral ?

  • Une entreprise européenne : Mistral AI est une société française. Son API est hébergée dans l'Union européenne par défaut.
  • Des modèles ouverts : une grande partie de la gamme est publiée en open-weight sous licence Apache 2.0. Tu peux télécharger ces modèles et les faire tourner chez toi, sans aucun appel extérieur.
  • AI Act : Mistral a signé le code de bonnes pratiques européen pour les modèles d'IA à usage général (juillet 2025) et publie pour ses modèles le résumé des données d'entraînement exigé par l'AI Act.

⚠️ Fournisseur conforme ne veut pas dire déploiement conforme

Les obligations de l'AI Act qui pèsent sur Mistral concernent le fournisseur du modèle. Toi, en tant que déployeur, tu restes responsable de la formation de tes équipes, de la transparence envers les personnes, du RGPD (base légale, AIPD, contrat de sous-traitance) et des obligations renforcées si ton usage est à haut risque. C'est l'objet de la session 7.

Option 1 — Mistral en local avec Ollama

Les petits modèles Ministral 3 (3B, 8B, 14B, licence Apache 2.0) savent appeler des outils et acceptent un long contexte : ils conviennent bien à un agent sur un ordinateur portable.

bash
# Télécharger un modèle Mistral open-weight
ollama pull ministral-3:8b

# L'utiliser comme modèle de l'agent
openclaw models set ollama/ministral-3:8b
openclaw models list --provider ollama

Avec 32 Go de RAM ou un GPU confortable, mistral-small3.2 (24B) est plus fiable sur les tâches longues.

Option 2 — L'API Mistral

Le fournisseur Mistral est un plugin officiel à installer, puis on renseigne sa clé API (créée dans la console Mistral) :

bash
openclaw plugins install @openclaw/mistral-provider
openclaw onboard --auth-choice mistral-api-key
openclaw models list --provider mistral

Range la clé dans ~/.openclaw/.env (MISTRAL_API_KEY=...), jamais dans le workspace de l'agent.

Modèles disponibles dans OpenClaw 2026.11.3 :

IdentifiantUsage
mistral/mistral-large-latestModèle par défaut, le plus capable
mistral/mistral-medium-3-5Bon équilibre qualité/coût, raisonnement réglable
mistral/mistral-small-latestMistral Small 4, rapide, raisonnement réglable
mistral/codestral-latestCode

Les anciens modèles Magistral sont dépréciés : le raisonnement se règle désormais sur Small 4 et Medium 3.5.

Option 3 — L'hybride : local d'abord, Mistral en secours

json5 · openclaw.json
{
  agents: {
    defaults: {
      model: {
        primary: "ollama/ministral-3:8b",
        fallbacks: ["mistral/mistral-small-latest"],
      },
    },
  },
}

Les modèles de secours sont essayés dans l'ordre quand le modèle principal échoue. Documente ce choix dans ton registre RGPD : quand le secours se déclenche, la conversation part chez Mistral.

Un modèle par agent

Chaque agent peut avoir son propre modèle : un petit modèle local pour la veille, un modèle plus puissant pour l'analyse de documents.

json5 · openclaw.json
{
  agents: {
    entries: {
      veille:  { workspace: "~/.openclaw/workspace-veille", model: "ollama/ministral-3:8b" },
      analyse: {
        workspace: "~/.openclaw/workspace-analyse",
        model: { primary: "mistral/mistral-medium-3-5", fallbacks: [] },
      },
    },
  },
}

💡 Piège des modèles par agent

Sous forme de texte (model: "…"), le modèle d'un agent est strict : aucun modèle de secours n'est utilisé. Pour en ajouter, utilise la forme objet { primary, fallbacks: [...] }.

Personnaliser un modèle local avec un Modelfile

Ollama permet de créer ta propre variante d'un modèle : consignes intégrées, température, taille de contexte.

text · Modelfile
FROM ministral-3:8b
SYSTEM """Tu es un assistant professionnel francophone.
Tu réponds de façon concise, tu cites tes sources
et tu refuses de traiter des données de santé."""
PARAMETER temperature 0.3
PARAMETER num_ctx 32768
bash
ollama create forge-ministral -f Modelfile
openclaw models set ollama/forge-ministral

La personnalité détaillée reste dans SOUL.md et AGENTS.md (session 2). Le Modelfile sert plutôt aux réglages techniques et aux garde-fous qui doivent s'appliquer quel que soit l'agent. OpenClaw fixe lui-même la taille de contexte des modèles locaux (32 768 tokens) ; une valeur plus petite dans le Modelfile peut donc être remplacée.

La mémoire avec Mistral

Pour la recherche dans la mémoire, tu as deux options européennes :

json5 · openclaw.json
{
  memory: {
    search: { provider: "ollama", model: "nomic-embed-text" },   // 100 % local
    // ou : { provider: "mistral" }                               // API Mistral, modèle mistral-embed
  },
}

Rappel : sans ce réglage, la mémoire est envoyée à OpenAI pour calculer les embeddings.

Ce qu'il faut vérifier côté Mistral

  • Entraînement : selon Mistral, les données envoyées à l'API ne servent pas à entraîner ses modèles par défaut.
  • Conservation : une option de conservation zéro (zero data retention) existe sur demande pour les comptes payants.
  • Contrat : signe l'accord de traitement des données (DPA) de Mistral : c'est ton contrat de sous-traitance au sens de l'article 28 du RGPD.
  • Certifications : Mistral annonce SOC 2 Type II et ISO 27001/27701 ; les rapports sont sur son portail de confiance.
  • Cloud Act : utiliser Mistral directement ou en local évite l'exposition au droit américain ; passer par une marketplace américaine (Azure, AWS, Google Cloud) la réintroduit.

Ces conditions évoluent : vérifie-les sur le site de Mistral avant de les inscrire dans ta documentation de conformité.

Sécurité avancée des agents

Comprendre comment un agent se fait attaquer, appliquer une défense en profondeur sur OpenClaw et savoir réagir à un incident.

Pourquoi un agent est une cible à part

Un chatbot ne fait que répondre. Un agent agit : il lit tes fichiers, exécute des commandes, envoie des messages. Le risque devient maximal quand trois éléments sont réunis dans le même agent :

  1. l'accès à des données privées (fichiers, e-mails, mémoire) ;
  2. l'exposition à du contenu non fiable (pages web, documents, messages de tiers) ;
  3. un moyen de faire sortir des données (requêtes web, envoi de messages, commandes shell).

Un texte piégé dans une page web peut alors pousser l'agent à lire tes secrets puis à les envoyer ailleurs. Toute la suite de cette session consiste à casser ce triangle : retirer au moins un des trois éléments à chaque agent, et limiter les deux autres.

Défense en profondeur : sept couches

1. Le système

bash
# Un utilisateur dédié, sans droits d'administration
sudo useradd -m -s /bin/bash openclaw
sudo -iu openclaw
# Puis installer OpenClaw avec cet utilisateur

Active le chiffrement du disque (FileVault, BitLocker, LUKS) : tout ce qui est dans ~/.openclaw peut contenir des secrets.

2. Le réseau

  • Gateway sur loopback avec authentification par token (réglage par défaut : le garder).
  • Accès distant uniquement par tunnel SSH ou Tailscale en mode serve, jamais funnel.
  • Pare-feu de la machine : tout refuser en entrée sauf SSH.

3. Qui peut parler à l'agent

json5 · openclaw.json
{
  session: { dmScope: "per-channel-peer" },
  channels: {
    telegram: {
      dmPolicy: "allowlist",
      allowFrom: ["123456789"],
      groupPolicy: "allowlist",
      groups: { "*": { requireMention: true } },
    },
  },
}

allowlist n'accepte que les identifiants listés ; dmScope: "per-channel-peer" donne une session séparée à chaque interlocuteur, pour que personne ne voie l'historique d'un autre.

4. Les outils

Commence par la base durcie de la documentation, puis réactive au cas par cas :

json5 · openclaw.json
{
  tools: {
    profile: "messaging",
    deny: ["group:automation", "group:runtime", "group:fs", "sessions_spawn", "sessions_send"],
    fs: { workspaceOnly: true },
    exec: { security: "deny", ask: "always" },
    elevated: { enabled: false },
    agentToAgent: { enabled: false },
  },
}

Pour un agent qui doit lancer des commandes, préfère une liste blanche avec confirmation :

bash
openclaw exec-policy preset cautious

Une interdiction l'emporte toujours sur une autorisation. Attention : interdire write et edit ne rend pas exec inoffensif ; il faut restreindre exec lui-même.

5. La sandbox

Pour les conversations de groupe et tout ce qui touche à du contenu extérieur, isole toutes les sessions et monte le workspace en lecture seule :

json5 · openclaw.json
{
  agents: {
    defaults: {
      sandbox: { mode: "all", scope: "session", workspaceAccess: "ro" },
    },
  },
}

Par défaut, le conteneur n'a pas de réseau, son système est en lecture seule et il n'a aucun privilège : ne change ces réglages qu'en connaissance de cause.

6. Les skills et plugins

  • openclaw skills verify @auteur/skill --card avant toute installation, et lecture du SKILL.md : méfie-toi de toute « étape d'installation » qui demande de lancer une commande téléchargée.
  • N'installe des plugins que de sources de confiance : ils tournent dans le processus de la Gateway.
  • openclaw security audit --deep analyse aussi les plugins installés.

7. Les secrets

  • Clés dans ~/.openclaw/.env ou dans l'environnement du service, jamais dans le workspace : l'agent peut lire son workspace.
  • openclaw secrets audit --check repère les secrets en clair.
  • Bot de messagerie sur un numéro ou un compte dédié.

L'agent « lecteur » pour le contenu non fiable

Plutôt que de laisser ton agent principal lire le web, confie cette tâche à un agent séparé, sans accès aux fichiers ni aux commandes : il ne peut ni lire tes secrets ni agir, même s'il se fait piéger.

json5 · openclaw.json
{
  agents: {
    entries: {
      main:    { name: "Assistant", workspace: "~/.openclaw/workspace" },
      lecteur: {
        name: "Lecteur web",
        workspace: "~/.openclaw/workspace-lecteur",
        tools: { profile: "minimal", alsoAllow: ["web_fetch", "web_search"] },
        sandbox: { mode: "all", workspaceAccess: "none" },
      },
    },
  },
}

Surveiller en continu

bash
openclaw security audit --deep
openclaw secrets audit --check
openclaw status --all
openclaw logs --follow

bash
openclaw automations create "0 8 * * 1" \
  "Lance openclaw security audit --deep et résume les alertes critiques." \
  --name "Audit hebdo" --tz "Europe/Paris"

Réagir à un incident

Si l'agent a fait quelque chose d'anormal, ou si une faille touche ta version :

  1. Couper : openclaw gateway stop.
  2. Révoquer : nouveau token de Gateway (openclaw doctor --generate-gateway-token), révocation du token du bot dans @BotFather, rotation de toutes les clés API présentes sur la machine.
  3. Comprendre : relire les journaux et les sessions concernées, et ce que l'agent a écrit dans sa mémoire.
  4. Nettoyer : supprimer les skills suspects, openclaw memory forget sur les sessions compromises, mise à jour (openclaw update).
  5. Notifier : si des données personnelles ont pu fuir, la violation doit être notifiée à la CNIL dans les 72 heures (art. 33 RGPD), et aux personnes concernées si le risque est élevé (session 7).

Savoir documenter et justifier un agent IA au regard du RGPD et de l'AI Act, pour toi ou pour une organisation.

ℹ️ Ce module n'est pas un conseil juridique

Il donne une méthode et des repères à jour au 13 novembre 2026. Pour un déploiement en entreprise, fais valider ta documentation par ton DPO ou un juriste.

Qui est qui ?

Étape 3 — Faut-il une AIPD ?

L'analyse d'impact relative à la protection des données (AIPD, art. 35 RGPD) est obligatoire quand le traitement présente un risque élevé. En pratique, la CNIL demande une AIPD dès que deux critères de cette liste sont réunis :

  • usage innovant ou technologie nouvelle (un agent IA autonome en fait partie) ;
  • surveillance systématique des personnes ;
  • personnes vulnérables, dont les salariés vis-à-vis de leur employeur ;
  • données sensibles ou hautement personnelles ;
  • traitement à grande échelle ;
  • croisement de jeux de données ;
  • évaluation ou notation de personnes ;
  • décision automatisée avec effet juridique ou similaire ;
  • traitement qui empêche d'exercer un droit ou de bénéficier d'un service.

Un agent qui lit les e-mails et les fichiers des salariés coche presque toujours « technologie innovante » et « personnes vulnérables » : prévois une AIPD. La CNIL fournit un outil gratuit (logiciel PIA) pour la rédiger.

Étape 4 — Appliquer les principes du RGPD à l'agent

  • Minimisation : ne donne à l'agent que les dossiers, comptes et outils nécessaires (fs.workspaceOnly, tools.deny).
  • Conservation limitée : fixe une durée pour les conversations et la mémoire, et applique-la (suppression régulière, éventuellement par une automatisation).
  • Transparence : informe les personnes (salariés, clients) de l'usage de l'agent, de ses finalités et de leurs droits.
  • Droits des personnes : sache retrouver et effacer les données d'une personne, y compris dans la mémoire.
  • Sécurité : session 6.
bash
# Effacer une conversation et la retirer de la mémoire
openclaw sessions delete "<clé-de-session>" --yes
openclaw memory forget --agent main --session "<clé-de-session>"

Pense aussi aux informations rédigées par l'agent dans MEMORY.md et memory/ : relis-les et supprime ce qui concerne la personne.

Étape 5 — Dans une entreprise : les salariés

  • Information préalable : un dispositif qui collecte des informations sur les salariés doit leur être annoncé avant sa mise en place (Code du travail, art. L1222-4).
  • CSE : les outils permettant de contrôler l'activité des salariés doivent être présentés au comité social et économique avant leur introduction.
  • Pas de surveillance cachée : un agent ne doit pas servir à évaluer ou surveiller les salariés à leur insu. Un tel usage peut en outre relever du « haut risque » de l'AI Act.

Étape 6 — Les contrats et les transferts

  • Contrat de sous-traitance (art. 28) avec chaque fournisseur d'API de modèle : il fixe la finalité, la sécurité, la conservation et l'absence d'usage pour l'entraînement.
  • Transferts hors UE : un fournisseur américain est encadré par le Data Privacy Framework UE–États-Unis, validé par le Tribunal de l'UE en septembre 2025 mais contesté en appel. Le Cloud Act américain permet aussi aux autorités des États-Unis d'exiger des données d'une entreprise américaine, même stockées en Europe. Un modèle local ou un fournisseur européen supprime ces deux incertitudes.

Tes obligations concrètes

  • Art. 4 — Maîtrise de l'IA : prendre des mesures pour que les personnes qui utilisent l'agent comprennent ses capacités et ses limites. Une formation comme celle-ci, documentée, en fait partie.
  • Art. 50 — Transparence : les personnes doivent savoir qu'elles échangent avec une IA quand ce n'est pas évident. Si ton agent répond à des clients ou à des tiers sur Telegram ou WhatsApp, dis-le clairement dans son premier message (et dans SOUL.md). Les contenus générés publiés pour informer le public, ou les « deepfakes », doivent être signalés comme tels.
  • Art. 5 — Pratiques interdites : jamais de reconnaissance des émotions au travail, de manipulation, d'exploitation des vulnérabilités ou de catégorisation biométrique sensible.
  • Art. 26 — Haut risque : si l'agent sert au recrutement, à l'évaluation ou à la surveillance de salariés, il devient un système à haut risque : contrôle humain, conservation des journaux au moins six mois, information des représentants du personnel. Le plus simple est de ne pas confier ces usages à un agent autonome.

Tous ces points se règlent dans OpenClaw (sessions 3, 4 et 6).

Comparatif : choisir le bon agent

Situer OpenClaw parmi ses alternatives et savoir choisir, et justifier, l'outil adapté à un besoin.

Ce que tu sais déjà faire, quel que soit l'outil

OpenClaw a lancé une famille d'outils qui partagent les mêmes briques. Tout ce que tu as appris s'y transpose :

  • une passerelle qui relie l'agent à tes messageries ;
  • un modèle interchangeable, local ou distant ;
  • des fichiers de personnalité et de règles (SOUL.md, AGENTS.md ou équivalents) ;
  • des skills au format SKILL.md, devenu un standard partagé ;
  • une mémoire en fichiers et une recherche sémantique ;

Les profils en bref

OpenClaw — la référence

Le plus utilisé, le plus de canaux (une trentaine), le plus grand écosystème de skills (ClawHub) et une documentation complète. En contrepartie : une surface d'attaque large, un historique de failles en 2026 et des réglages par défaut permissifs qu'il faut durcir (session 6).

Hermes Agent — l'agent qui apprend

Il crée et améliore ses propres skills à l'usage et modélise son utilisateur. Il importe une installation OpenClaw en une commande (personnalité, mémoire, skills, listes d'accès). Mais sa propre politique de sécurité le dit : la seule vraie frontière face à un modèle malveillant est le système d'exploitation. Par défaut, les commandes s'exécutent directement sur ta machine. Plusieurs failles ont été publiées au printemps 2026.

bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
hermes import-agent openclaw --dry-run

NanoClaw — l'isolation d'abord

Une base de code volontairement petite, lisible en une après-midi. Chaque agent tourne dans son propre conteneur Linux et ne voit que ce qui y est explicitement monté ; les clés API passent par une passerelle d'identifiants et ne sont jamais confiées à l'agent. Il est conçu autour de Claude et de Claude Code (d'autres modèles, dont Ollama, s'ajoutent par des skills), et on le personnalise en modifiant son code plutôt qu'une configuration.

ZeroClaw — léger et embarqué

Un seul binaire Rust, peu gourmand, qui tourne jusque sur des cartes électroniques. Par défaut, il demande une approbation pour les actions à risque moyen et bloque les actions à haut risque. La sandbox du système (Landlock, Bubblewrap, Docker…) n'est active que si elle est disponible, et le projet est encore en version 0.x.

nanobot — la simplicité

Un petit cœur Python facile à lire et à modifier, compatible avec les skills SKILL.md et ClawHub. Ses réglages par défaut sont permissifs : pas de restriction au workspace ni de sandbox tant qu'on ne les active pas.

IronClaw — la sécurité par conception

Une réécriture en Rust inspirée d'OpenClaw : les outils non fiables tournent dans une sandbox WebAssembly avec des permissions explicites, les secrets sont chiffrés et injectés hors de portée du modèle, sans télémétrie. Moins de canaux (pas encore WhatsApp) et un développement moins actif depuis septembre 2026.

Et les agents hébergés ?

Claude Cowork (Anthropic), Perplexity Computer ou Manus n'exigent aucune installation : l'agent tourne dans le cloud du fournisseur. C'est plus simple et souvent plus capable, mais tes fichiers et conversations sont traités sur leurs serveurs, en général hors de l'UE. On revient alors aux questions de la session 7 : contrat de sous-traitance, transferts, Cloud Act.

Comment choisir : les six questions

  1. Quelles données l'agent touchera-t-il ? Données personnelles ou sensibles : local ou fournisseur européen, isolation forte.
  2. Qui lui parlera ? Toi seul, ou des collègues et des clients (contrôle d'accès, transparence AI Act).
  3. Que doit-il pouvoir faire ? Lire, écrire, exécuter, envoyer : chaque capacité ajoutée doit être justifiée.
  4. Quelle isolation par défaut ? Un outil isolé par conception (NanoClaw, IronClaw) pardonne plus d'erreurs de configuration.
  5. Qui maintiendra l'installation ? Mises à jour de sécurité fréquentes : prévois le temps, ou choisis un outil plus petit.
  6. Quel écosystème te faut-il ? Canaux, skills, documentation, communauté : l'avantage d'OpenClaw.

💡 Le bon réflexe

Quel que soit l'outil, applique la même méthode : cartographie des flux, moindre privilège, isolation, journalisation, mises à jour. C'est ce qui rend un agent sûr, bien plus que le nom du logiciel.

📖 Glossaire

GatewayLe serveur central d'OpenClaw
▼

Processus qui tourne en permanence sur ta machine (port 18789, accessible seulement en local par défaut). Il reçoit les messages des canaux, les route vers le bon agent et conserve les sessions.

AgentL'assistant
▼

Une instance d'assistant avec son workspace, son modèle et sa mémoire. L'agent par défaut s'appelle main ; on peut en déclarer plusieurs dans agents.entries.

WorkspaceLe dossier de l'agent
▼

Dossier (par défaut ~/.openclaw/workspace) qui contient AGENTS.md, SOUL.md, USER.md, la mémoire et les skills de l'agent. Ce n'est pas une sandbox : c'est son répertoire de travail.

LLMLarge Language Model
▼

Modèle de langage qui sert de moteur de raisonnement à l'agent. Dans ce cours, il tourne en local avec Ollama (par exemple gemma4).

OllamaRuntime local pour LLM
▼

Outil open source qui télécharge et exécute des modèles sur ta machine. OpenClaw l'utilise via son API native sur le port 11434 (pas l'URL /v1).

CanalMessagerie connectée
▼

Telegram, WhatsApp, Signal, Discord… : les applications depuis lesquelles tu parles à l'agent. Les inconnus doivent être approuvés (appairage).

SkillSavoir-faire installable
▼

Dossier contenant un SKILL.md qui explique à l'agent comment accomplir une tâche. On les trouve sur ClawHub ; un skill tiers doit être traité comme du code non fiable.

EmbeddingReprésentation vectorielle
▼

Transformation d'un texte en vecteur numérique. Deux textes proches en sens ont des vecteurs proches : c'est ce qui permet la recherche dans la mémoire de l'agent.

SandboxExécution isolée
▼

Conteneur Docker dans lequel l'agent exécute ses outils, sans réseau et avec un système en lecture seule par défaut. Réduit les dégâts possibles, sans être une frontière parfaite.

Injection de promptInstructions cachées
▼

Texte malveillant glissé dans une page web, un e-mail ou un document pour détourner l'agent. Parade : outils restreints, sandbox, agent en lecture seule pour les contenus douteux.

RGPDRèglement général sur la protection des données
▼

Réglementation européenne sur les données personnelles. Un agent local aide à s'y conformer, à condition de vérifier où partent les données (modèle, embeddings, mises à jour).

Open-weightModèle aux poids publiés
▼

Modèle dont les paramètres sont téléchargeables (par exemple Ministral 3 sous licence Apache 2.0). On peut le faire tourner chez soi, sans envoyer de données à son éditeur.

AIPDAnalyse d'impact relative à la protection des données
▼

Étude obligatoire (art. 35 RGPD) quand un traitement présente un risque élevé ; en pratique dès que deux critères de la liste de la CNIL sont réunis.

AI ActRèglement européen sur l'IA
▼

Règlement (UE) 2024/1689. Il distingue le fournisseur d'un modèle ou système et le déployeur qui l'utilise ; chacun a ses propres obligations.

DéployeurUtilisateur professionnel d'un système d'IA
▼

Au sens de l'AI Act, l'organisation qui utilise un système d'IA sous sa propre autorité. Il doit notamment former ses utilisateurs (art. 4) et informer les personnes (art. 50).

Défense en profondeurSécurité par couches
▼

Empiler plusieurs protections indépendantes (système, réseau, accès, outils, sandbox, skills, secrets) pour qu'une seule défaillance ne suffise pas à compromettre l'agent.
