Prérequis & Installation

Avant de lancer ton premier agent, assure-toi que ton environnement est propre. Cette section couvre tout : de l'OS aux permissions en passant par Docker et Ollama.

Prérequis Système

✅ Requis

  • • OS : macOS 12+, Ubuntu 22.04+, Windows 11 + WSL2
  • • RAM : 8 Go minimum (16 Go recommandé pour Llama 3 8B)
  • • Disque : 20 Go libres (modèles LLM volumineux)
  • • Node.js : v20+ LTS
  • • npm : v10+
  • • curl : installé par défaut (Linux/macOS)

🌟 Recommandé

  • • GPU : NVIDIA (CUDA) ou Apple Silicon (Metal) pour inférence rapide
  • • Docker : v24+ pour la sandbox isolée
  • • VS Code : avec extension REST Client
  • • Git : pour cloner les templates
  • • PM2 : pour déploiement 24/7

Étape 1 — Installer Ollama

Ollama est le moteur d'inférence local qui fait tourner tes LLMs. Il expose une API REST sur localhost:11434. Zéro donnée ne quitte ta machine.

🐧🍎 Linux & macOS
▼
bash
# Installation one-liner officielle
curl -fsSL https://ollama.com/install.sh | sh

# Vérifier l'installation
ollama --version

# Démarrer le service en arrière-plan
ollama serve &
🪟Windows (WSL2)
▼
powershell + wsl
# Activer WSL2 (PowerShell admin)
wsl --install -d Ubuntu-22.04

# Dans WSL2 Ubuntu
curl -fsSL https://ollama.com/install.sh | sh

# OU télécharger l'installer natif Windows
# https://ollama.com/download/OllamaSetup.exe

Étape 2 — Pull du modèle LLM

OpenClaw est optimisé pour Llama 3 8B. Le modèle est téléchargé localement (~5 Go). Choisir la version q8_0 pour la meilleure qualité.

bash
# Modèle recommandé (8B params, qualité maximale)
ollama pull llama3:8b-instruct-q8_0

# Version légère si RAM < 8Go
ollama pull llama3:8b-instruct-q4_0

# Vérifier les modèles installés
ollama list

# Test rapide API locale
curl http://localhost:11434/api/generate \
  -H "Content-Type: application/json" \
  -d '{"model":"llama3","prompt":"Bonjour, es-tu opérationnel ?","stream":false}'

💡 Comprendre la réponse API

L'API Ollama retourne un JSON avec response (le texte généré), done:true et des métriques de performance. En mode stream:true, les tokens arrivent en temps réel (Server-Sent Events).

Foundations & Architecture

Comprendre comment Ollama, le SDK OpenClaw et ton système s'articulent. Pourquoi le local surpasse le cloud sur tous les critères qui comptent.

L'Architecture en 3 Couches

🧠

Couche LLM

Ollama + Llama 3
Inférence locale pure

🦞

Couche Agent

SDK OpenClaw
Boucle Perception→Action

🛡️

Couche Sécurité

Sandbox Docker
Audit + RGPD

La force de cette architecture : chaque couche est interchangeable et auditable. Tu peux remplacer Llama 3 par Mistral, la sandbox par systemd, sans toucher au reste.

La Boucle OpenClaw : Perception → Réflexion → Action → Observation

P

Perception

L'agent reçoit une tâche (texte, fichier, API call). Il parse l'input et extrait les intentions avec le LLM.

R

Réflexion

Le LLM analyse la tâche, sélectionne les outils disponibles, planifie les étapes nécessaires.

A

Action

L'agent exécute : appel d'outil, écriture de fichier, requête HTTP — toujours dans la sandbox.

O

Observation

L'agent lit le résultat de l'action, le réinjecte dans le contexte, décide de continuer ou de s'arrêter.

Créer ton Premier Agent

De la théorie à l'exécution. Tu vas initialiser un agent Lobster-01, lui donner des outils, et le regarder exécuter sa première tâche autonome.

Initialiser le Projet

OpenClaw utilise des templates pour scaffolder un agent en quelques secondes. Le template autonomous-researcher est le point de départ idéal.

bash
# Créer le dossier de ton agent
mkdir lobster-01 && cd lobster-01

# Initialiser avec le template de recherche
openclaw init --template autonomous-researcher

# Structure créée :
# lobster-01/
# ├── agent.config.json   ← configuration de l'agent
# ├── tools/              ← tes outils custom
# ├── memory/             ← stockage local RAG
# └── logs/               ← audit trail complet

Configurer agent.config.json

Ce fichier est le cerveau de ton agent. Chaque champ a un impact direct sur le comportement. Décortique chaque paramètre.

json · agent.config.json
{
  "name": "Lobster-01",
  "version": "1.0.0",
  "model": "llama3:8b-instruct-q8_0",
  "role": "Agent de recherche autonome spécialisé IA",
  "goal": "Extraire, synthétiser et livrer les news IA toutes les 6h",
  "tools": ["web-search", "file-writer", "markdown-formatter"],
  "constraints": "Strictement local. Jamais de clé API externe. Format Markdown uniquement.",
  "memory": { "type": "local", "path": "./memory" },
  "sandbox": { "enabled": true, "driver": "docker" },
  "maxIterations": 10,
  "timeout": 120000
}
model : pointe vers le modèle Ollama exact. Changeable à chaud.
tools : liste des outils autorisés. L'agent NE PEUT PAS utiliser d'autres outils.
sandbox.driver : docker isole l'exécution. Utilise none pour désactiver (déconseillé).
maxIterations : évite les boucles infinies. Toujours définir une limite.

Lancer et Tester l'Agent

bash
# Mode développement (logs verbeux)
openclaw run agent.config.json --verbose

# Mode production + audit trail
openclaw run agent.config.json --audit

# Lancer avec une tâche spécifique
openclaw run agent.config.json \
  --task "Résume les 5 dernières avancées en LLM"

# Test en sandbox isolée
openclaw run --sandbox agent.config.json

# Voir les logs en temps réel
tail -f logs/agent.log

⚠️ Bonne pratique : Toujours démarrer avec --audit

Le flag --audit génère un journal complet de chaque décision de l'agent : quel outil, quelle entrée, quelle sortie. Indispensable pour déboguer et pour la conformité RGPD.

RAG Local — L'agent lit tes docs privés

Retrieval-Augmented Generation (RAG) = l'agent peut interroger tes PDF, Markdown, CSV. Rien ne quitte ton réseau. Le module LocalMemory gère l'indexation et la recherche sémantique localement.

javascript · rag-setup.js
import { LocalMemory, Agent } from '@openclaw/sdk';

// Indexer ton dossier de documents
const memory = new LocalMemory({
  path: './my-private-docs',
  embedModel: 'nomic-embed-text',  // via Ollama
  chunkSize: 512,
  overlap: 64
});

// Indexer (première fois, puis incrémental)
await memory.index();
// ✅ Indexé 47 documents, 1,203 chunks

// Attacher la mémoire à l'agent
const agent = new Agent('./agent.config.json');
await agent.attach(memory);

// L'agent interroge maintenant tes docs locaux
const result = await agent.run(
  "Que dit notre politique RGPD sur la rétention ?"
);
console.log(result.answer);  // Réponse basée sur TES docs

Notifications Telegram (Serveur Local)

Envoyer les résumés de l'agent sur Telegram via un bot local. Utiliser Tailscale pour un tunnel privé sans exposer de port public.

javascript · notifier.js
// Hook de notification — s'exécute après chaque tâche
import { createHook } from '@openclaw/hooks';

const notify = createHook('on-task-complete', async (result) => {
  // Appel ton serveur Telegram local (bot self-hosted)
  await fetch(`http://localhost:8080/notify`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      message: `🦞 Agent Lobster-01\n\n${result.summary}\n\nTokens: 0€ (local)`
    })
  });
});

// Attacher le hook à l'agent
agent.use(notify);

Créer un Outil Custom

Un outil OpenClaw = une fonction TypeScript avec un schéma JSON pour que le LLM sache comment l'appeler. Exemple : scraper de news.

typescript · tools/news-scraper.ts
import { defineTool } from '@openclaw/sdk';

export const newsScraper = defineTool({
  name: 'fetch-ai-news',
  description: 'Récupère les dernières news IA depuis les flux RSS locaux',
  schema: {
    type: 'object',
    properties: {
      source: { type: 'string', enum: ['arxiv', 'hn', 'local-rss'] },
      limit: { type: 'number', default: 5 }
    },
    required: ['source']
  },
  async execute({ source, limit }) {
    // Logique de scraping locale
    const items = await fetchLocalRSS(source, limit);
    return items.map(i => ({ title: i.title, summary: i.snippet }));
  }
});

Architecture Multi-Agents

Un orchestrateur délègue des sous-tâches à des agents spécialisés. Chacun tourne dans sa sandbox. Communication via un bus local.

typescript · orchestrator.ts
import { Orchestrator, Agent } from '@openclaw/sdk';

const orchestrator = new Orchestrator();

// Agent 1 : Collecteur de données
const collector = new Agent({ name: 'data-collector', tools: ['web-search'] });

// Agent 2 : Analyseur
const analyzer = new Agent({ name: 'analyzer', tools: ['file-reader', 'summarizer'] });

// Agent 3 : Rédacteur
const writer = new Agent({ name: 'writer', tools: ['file-writer'] });

orchestrator.pipeline([collector, analyzer, writer]);
await orchestrator.run("Rapport hebdomadaire IA");

Sécurité & RGPD France / Europe

La philosophie OpenClaw : Privacy by Design. Chaque décision technique est pensée pour maximiser la souveraineté des données et la conformité réglementaire.

Principes de Sécurité

🛡️ Privacy by Design

  • • Zéro donnée hors réseau local par défaut
  • • Chiffrement au repos (option AES-256)
  • • Audit trail immuable (--audit flag)
  • • Pas de télémétrie, pas d'analytics

⚠️ Risques à Éviter

  • • Ne jamais exposer l'API Ollama sur 0.0.0.0
  • • Ne pas exécuter l'agent en root
  • • Ne jamais désactiver la sandbox en prod
  • • Éviter les clés API dans le config.json

Hardening — Commandes de Sécurité

bash · sécurisation
# Créer un utilisateur dédié non-root pour l'agent
sudo useradd -m -s /bin/bash openclaw-agent
sudo -u openclaw-agent openclaw run agent.config.json

# S'assurer qu'Ollama n'écoute que localhost
# Dans /etc/ollama/config (ou variable d'env)
OLLAMA_HOST=127.0.0.1:11434

# Vérifier avec netstat
ss -tlnp | grep 11434
# Doit afficher 127.0.0.1:11434 (pas 0.0.0.0)

# Stocker les secrets dans .env (jamais dans config.json)
echo "TELEGRAM_BOT_TOKEN=xxx" >> .env
chmod 600 .env

# Firewall UFW — bloquer tout sauf le nécessaire
sudo ufw default deny incoming
sudo ufw allow ssh
sudo ufw enable

📖 Glossaire

LLMLarge Language Model
▼

Modèle de langage de grande taille, entraîné sur des milliards de tokens de texte. Exemples : Llama 3, Mistral, Gemma. Dans OpenClaw, le LLM est le moteur de raisonnement de l'agent.

RAGRetrieval-Augmented Generation
▼

Technique permettant à un LLM d'interroger une base de documents externe avant de générer sa réponse. Dans OpenClaw, le RAG est 100% local : l'agent lit tes PDFs mais aucune donnée ne quitte ton réseau.

SandboxEnvironnement isolé d'exécution
▼

Conteneur Docker isolé dans lequel l'agent exécute ses actions. Il ne peut pas accéder aux fichiers système en dehors du dossier autorisé, ni sortir sur internet sans règle explicite.

EmbeddingReprésentation vectorielle
▼

Transformation d'un texte en un vecteur numérique de haute dimension (ex: 768 valeurs). Deux textes sémantiquement proches auront des vecteurs proches. Utilisé pour la recherche dans le RAG.

Tool CallingAppel d'outils par le LLM
▼

Mécanisme par lequel le LLM peut décider d'appeler une fonction externe (recherche web, écriture de fichier, etc.) en générant un JSON structuré. OpenClaw intercept ces appels et les exécute dans la sandbox.

RGPDRèglement Général sur la Protection des Données
▼

Réglementation européenne (2018) sur la protection des données personnelles. Applicable à toute organisation traitant des données de résidents UE. OpenClaw local est nativement RGPD-compliant : aucune donnée ne sort de l'infrastructure contrôlée.

OllamaRuntime local pour LLMs
▼

Outil open-source qui permet de télécharger et d'exécuter des LLMs localement. Il expose une API REST compatible OpenAI sur le port 11434. Supporte Mac (Metal), Linux (CUDA/CPU), Windows (WSL2).
